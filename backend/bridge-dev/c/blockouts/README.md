# 구도 참고 이미지(Blender 블록아웃) 가이드

C 훅의 첫 장면(문제 상황)을 **정해 둔 구도에서 시작하게** 만드는 방법입니다. Blender 로 만든 회색 상자 수준의 장면(블록아웃)을 한 장 렌더해 두면, 훅을 만들 때 이미지 모델이 그 그림을 같은 구도의 실사 화면으로 바꾸고, 영상 모델이 그 화면에서 이어지는 클립을 만듭니다.

```text
Blender 블록아웃 (미리 렌더한 PNG, 이 폴더)
   └─▶ 이미지 모델(Nano Banana): 같은 구도의 실사 첫 프레임
          └─▶ 영상 모델(Gemini Omni): 그 화면에서 시작하는 클립  ─▶  훅의 첫 장면
```

쓰지 않아도 됩니다. 구도를 고르지 않은 시나리오는 지금까지와 똑같이 글만으로 만들어집니다.

## 왜 쓰나

글만으로 만든 문제 장면은 카메라 위치와 소품 배치가 요청마다 달라집니다. 블록아웃을 주면 카메라 각도, 소품 위치, 손이 들어오는 방향이 고정되어 훅 첫 3초의 화면을 의도대로 잡을 수 있습니다. 겉모습(재질·빛)은 이미지 모델이 그리므로 Blender 에서는 구도만 잡으면 됩니다.

| 블록아웃 (`phone_distract.png`) | 하는 일 |
| --- | --- |
| 책상 POV, 펼친 노트·펜·스마트폰·노트북·머그잔, 노트 위의 오른손 | 이미지 모델이 나무 책상·실제 손으로 바꾸고, 영상 모델이 "손이 폰을 집어 넘겨 본다"를 그 화면에서 이어 만듭니다 |

## 동작 순서

1. **시나리오 (C 작업자, `src/`)**: 프롬프트에 이 폴더의 구도 목록(`catalog.json`)이 들어갑니다. 글 모델은 첫 장면이 목록의 상황과 같을 때만 `problem_blockout` 에 그 `id` 를 적습니다. 구도에 맞추려고 문제 상황을 바꾸지 않도록 지시합니다.
2. **장면에 붙이기 (`src/blockouts.py`)**: 고른 `id` 가 목록에 있으면 첫 장면에 두 값을 붙입니다. 목록에 없는 값은 무시합니다.

   ```json
   {
     "order": 1, "role": "문제", "...": "...",
     "first_frame_ref": "c/blockouts/phone_distract.png",
     "first_frame_prompt": "Turn this rough gray-box 3D blockout into a photorealistic photo …"
   }
   ```

   `ad_spec.problem_blockout` 에도 고른 `id` 를 남깁니다.
3. **훅 만들기 (`backend/hookpipe/render.py`)**: 장면에 `first_frame_ref` 가 있으면
   - 이미지 모델에 블록아웃과 `first_frame_prompt` 를 보내 실사 첫 프레임을 받습니다 (`generate_reference_image(..., anchor_paths=[블록아웃])`).
   - 영상 모델에 그 첫 프레임을 넘겨 클립을 만듭니다 (`generate_video_clip(..., first_frame_path=…)`).
   - 그 장면에는 톤 참고 이미지를 넣지 않습니다. 화면의 톤은 첫 프레임이 정합니다.

## 장면에 쓸 수 있는 값

| 값 | 뜻 |
| --- | --- |
| `first_frame_ref` | 구도 참고 이미지 위치. 작업자 폴더(`HOOK_WORKERS_DIR`, 기본 `backend/bridge-dev`) 아래의 상대 경로를 먼저 찾고, 없으면 미리 만든 소재(`prebuilt_clip`)와 같은 방식(`HOOK_ASSETS_DIR` · 저장소 키)으로 찾습니다. 폴더 밖을 가리키는 경로는 받지 않습니다. |
| `first_frame_prompt` | 이미지 모델에 줄 실사화 지시(영어). 없으면 기본 지시를 씁니다. |
| `first_frame_refine` | `false` 면 이미지 모델을 거치지 않고 그 이미지를 그대로 첫 프레임으로 씁니다. 이미 사진처럼 보이는 그림일 때만 씁니다. 회색 상자 블록아웃을 그대로 넘기면 그 겉모습이 영상에 남습니다. |

C 가 아닌 유형의 시나리오에도 같은 값을 쓰면 똑같이 동작합니다.

## 실패했을 때

구도 참고는 품질 보조라서, 어느 단계가 실패해도 훅은 만들어집니다. 이유는 `render_meta.json` 의 `warnings` 에 남습니다.

| 상황 | 동작 |
| --- | --- |
| 이미지를 찾지 못함 | 경고를 남기고 그 장면을 글만으로 만듭니다 |
| 이미지 모델이 첫 프레임을 만들지 못함 | 경고를 남기고 그 장면을 글만으로 만듭니다 |
| 영상 모델이 첫 프레임이 든 요청을 거절함 (`INVALID_ARGUMENT`) | 첫 프레임 없이 같은 프롬프트로 다시 보냅니다 (거절된 요청은 과금되지 않습니다) |
| 그 장면에 미리 만든 영상(`prebuilt_clip`)이 있음 | 미리 만든 영상을 쓰고, 구도 참고를 쓰지 않았다는 경고를 남깁니다 |

## 영상 엔진별 동작

구도 참고는 hookpipe 가 장면 클립을 **직접 영상 모델에 요청할 때** 쓰입니다.

| 엔진 | 구도 참고 |
| --- | --- |
| 구글 모델 (`HOOK_MEDIA_ENGINE=gemini`, 로컬 기본값) | 쓰입니다. 이 문서의 동작 순서 그대로입니다 |
| 자체 모델 (`HOOK_MEDIA_ENGINE=selfhosted`, PR #22 · Modal 배포 기본값) | **쓰이지 않습니다.** 이 엔진은 장면마다 FLUX 스틸컷 → MiniMax 클립을 만들어 `prebuilt_clip` 으로 넣기 때문에, 위 표의 마지막 줄대로 경고만 남습니다. 시나리오의 `first_frame_ref` 와 `ad_spec.problem_blockout` 은 그대로 남아 있으므로, 이 엔진의 콘티 단계가 장면 1을 그릴 때 블록아웃을 참고 이미지로 넘기도록 잇는 것은 후속 작업입니다 |

## 비용

구도를 쓴 장면 하나에 이미지 모델 호출 1회가 더 듭니다. 대신 그 장면만 있는 훅이면 톤 참고 이미지 1회가 빠집니다. 영상 모델 호출 수는 그대로입니다. 받은 첫 프레임과 클립은 `_cache` 에 남아, 같은 블록아웃·지시·모델이면 다시 사지 않습니다.

## 새 구도 추가하기

1. **Blender 로 구도 잡기.** `blender_scene_desk.py` 가 예시입니다. Blender 창 안에서 그대로 실행하면(Blender MCP 로 실행해도 됩니다) 새 장면이 만들어져 카메라·소품을 눈으로 보며 고칠 수 있습니다. 상자·원기둥 수준이면 충분합니다. 9:16(1080×1920)으로 잡습니다.
2. **한 장 렌더.** 창 없이 실행해 프레임 하나만 뽑고 720×1280 PNG 로 줄입니다.

   ```bash
   blender -b -P blender_scene_desk.py -- out_dir assets_dir 100 1 1     # out_dir/p_0001.jpg
   ffmpeg -i out_dir/p_0001.jpg -vf scale=720:1280 my_scene.png
   ```

   글자·로고·얼굴은 넣지 않습니다. 영상 모델이 따라 그립니다.
3. **목록에 등록.** `catalog.json` 에 항목을 추가합니다.

   | 값 | 뜻 |
   | --- | --- |
   | `id` | 글 모델이 고르는 이름 (영문 소문자와 `_`) |
   | `description` | 어떤 상황의 구도인지 한국어 한두 문장. 글 모델은 이 문장만 보고 고르므로 시점, 보이는 물건, 상황을 적습니다 |
   | `image` | `c/blockouts/<파일>.png` (`HOOK_WORKERS_DIR` 기준) |
   | `refine_prompt` | 이미지 모델에 줄 실사화 지시(영어). 구도는 그대로 두고 무엇을 어떤 재질로 바꿀지 적습니다 |
   | `source` | 어떤 스크립트의 몇 번 프레임인지 (기록용) |
4. **확인.** `python test/mock_run.py` 가 목록의 이미지 파일이 실제로 있는지까지 검사합니다.

## 테스트

과금 호출 없이 돕니다.

```bash
cd backend/bridge-dev/c && python test/mock_run.py          # 7번: 목록 읽기, 프롬프트, 첫 장면에 붙이기
.venv/bin/python scripts/test-python.py hookpipe            # 첫 프레임 단계 4건 (저장소 루트에서)
```

## 확인한 것과 아직 아닌 것

- **실제 모델로 확인한 것 (2026-11-27, Google Cloud 무료 체험 계정):** `phone_distract.png` → `gemini-nano-banana-2.1` 실사 첫 프레임 → `gemini-omni-1.2-flash` 4초 클립. 책상 구도와 소품 배치가 유지됐고 손이 폰을 집어 넘겨 보는 영상이 나왔습니다. 같은 첫 프레임으로 `veo-3.1-fast-generate-001` 도 됐습니다. 이 확인은 `상윤` 브랜치의 C 로컬 코드에서 REST 로 직접 부른 것입니다.
- **hookpipe 경로로도 확인했습니다 (2026-11-27, 구글 모델 엔진, 로컬 풀스택):** 프론트 → `backend/app` → hookpipe → C 작업자(Gemini)로 타이머 제품을 넣었을 때 글 모델이 `phone_distract` 를 골랐고, 첫 프레임 이미지와 첫 장면 클립이 경고 없이 만들어졌습니다 (최종 영상 26초: 훅 16초 + 본편 10초). 당시 Vertex 에서 이미지 모델이 Interactions API 로 거절되던 문제는 지금 `main` 에서 고쳐져 있습니다.
- **아직 확인하지 않은 것:** 자체 모델 엔진과 함께 쓰는 경우(위 "영상 엔진별 동작"), Claude 를 글 모델로 썼을 때 `problem_blockout` 을 고르는지.
- **알려진 한계:** 자체 모델 엔진에서는 쓰이지 않습니다(위 "영상 엔진별 동작"). 구도가 하나뿐입니다(책상 POV). Omni 는 무료 체험 계정에서 거절된 날이 있었습니다(2026-11-26).
